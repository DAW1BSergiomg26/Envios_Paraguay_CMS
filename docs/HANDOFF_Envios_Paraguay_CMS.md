## 8. Problemas conocidos

### Archivo sin seguimiento

Existe un archivo no añadido a Git:

```bash
estructura.txt
```

Antes de hacer nuevos commits, decidir si:

* se añade al repositorio como documentación,
* se mueve a una carpeta `docs/`,
* o se elimina si solo era temporal.

### Muchas ramas acumuladas

El proyecto tiene muchas ramas feature.

Riesgo:

* confusión,
* duplicación de trabajo,
* pérdida de trazabilidad,
* dificultad para saber qué está integrado realmente.

Recomendación:

* revisar ramas fusionadas,
* borrar ramas obsoletas solo después de comprobar,
* mantener `develop` como base principal de integración.

### Posible acumulación de CSS

Por los commits, existen muchas mejoras visuales separadas.

Riesgo:

* CSS duplicado,
* estilos que pisan otros estilos,
* dificultad de mantenimiento.

Recomendación:

* auditar CSS premium,
* agrupar estilos por sección,
* evitar romper home, operaciones y tracking.

### Consistencia ES/EN

Muchas mejoras se hacen en español e inglés.

Riesgo:

* una versión queda más avanzada que otra,
* textos desalineados,
* rutas o headers inconsistentes.

Recomendación:

* cada mejora visual debe verificarse en ES y EN.
